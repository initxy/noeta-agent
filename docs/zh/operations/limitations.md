# 已知限制

这些是产品刻意划下的边界，不是 bug。每条说明它是什么、什么时候会撞上、有没有变通。
症状形态的问题见[排障](troubleshooting.md)。

## `local` 层没有隔离，也没有授权关卡

**含义：** `local` 层的项目，agent 的文件与 shell 工具**以你的身份跑在你的机器上**。
没有容器，整个产品也没有逐次授权弹窗 —— 权限是按设计旁路的：没有界面去回答它，而一轮
停在无人能答的授权上就是一个挂死的对话。

- **文件写入被围在项目目录内。** 越界的 `write` / `edit` / `apply_patch` 直接失败；
  既然没有授权流程可以临时开口子，这道墙就是绝对的。
- **`shell_run` 不受围栏约束。** 一条 shell 命令能读、能写、能删你自己能动的一切。

**何时撞上：** 任何 `local` 项目 —— 也就是默认且常见的情况。

**变通：** 不想让 agent 碰到机器其它部分的活儿，选 `sandbox` 层；并且保持服务绑在
`127.0.0.1`（默认）—— 暴露出去的工作台等于一个无鉴权的远程 shell。

**为什么这样：** [execution-tier-per-project](../../adr/execution-tier-per-project.md)（英文）。

## 会话的执行层无法更改

**含义：** 执行层在会话第一条消息 seed 任务时解析一次，并焊进那个 task；之后每一轮都
从那里解析。

**何时撞上：** 你把项目从 `local` 改成 `sandbox`，而已有会话依旧在本机跑。

**变通：** 新建一个会话。界面在该控件旁就是这么写的。

**为什么这样：** 运行时要求这个回调对同一会话是确定性的；一个中途换了执行环境的任务，
会把它的文件写在两个世界里。

## 一个项目的会话共用一个目录，且没有锁

**含义：** 项目的所有会话都以项目目录为 workspace 根。两个活跃会话 —— 或者一个会话和
你自己的编辑器 —— 可能同时写同一个文件。没有任何仲裁。

**何时撞上：** 并行跑两轮、动同一批文件。

**变通：** 没有自动方案，但有两处是围着它设计的：artifact 保存带乐观锁（冲突是一个让你
回答的 **409**，不是静默覆盖），以及 **`rewind`（"撤回上一轮"）在还原文件时带显式警告**
——因为还原一个会话的文件会回退另一个会话的成果，所以撤回只在 root 会话的最新一轮上提供，
并在点击前说明风险。

**为什么这样：** [project-model](../../adr/project-model.md)（英文）。

## 单用户、单进程、无鉴权

**含义：** 没有登录、没有用户模型、没有共享，API 里也没有任何授权。应用状态是本地
SQLite 文件。这个产品就是要跑在你自己的机器上。

**何时撞上：** 任何"要不要放到网络上"的念头。

**变通：** 没有 —— 这就是产品本身。需要多用户的话，那是另一个产品（正是这次重写刻意
删掉的那个）。

## 一部分能力开关没有读者

**含义：** `MEMORY_TOOLS_ENABLED`、`SUBAGENT_ENABLED`、`MEMORY_CONSOLIDATION`、
`MEMORY_CONSOLIDATION_DEBOUNCE_HOURS`，以及**项目 Settings → Memory 里的开关**，都只是
被存下来而没有被读。记忆与子 agent 工具由 agent preset 无条件挂载，记忆整理从未被触发。

**何时撞上：** 你为某个项目关掉记忆，agent 照样召回。

**变通：** 目前没有。按项目切换需要在 seed 时选择第二套编译好的 agent recipe；整理则
需要宿主去调用 SDK 那一 pass。

## MCP 连接器配置有测试，握手没有

**含义：** 连接器记录、作用域、凭证擦除，以及交给引擎的 spec 形状都有测试覆盖。没有被
自动化覆盖的是"线上那一半"：启用的连接器在任务开始时是否真的完成了握手、凭证是否真的
在请求上，以及禁用的连接器是否真的没碰网络。

**何时撞上：** 一个看起来配好了、却从没出现在模型工具列表里的连接器。

**变通：** 看一轮开始时的后端日志，以及 trace 页面里这一轮实际拿到的工具。

## sandbox 的隔离是进程 + 挂载文件系统

**含义：** 容器只看到被挂进去的目录，而不是宿主机根 —— 但项目目录是 bind mount，对它的
写入会直接落到宿主机文件系统上。它不是完整的文件系统或网络牢笼；
`--security-opt seccomp=unconfined` 是 AIO 镜像自身的要求。

**何时撞上：** 真正不可信的代码。

**变通：** 把整个工作台放进虚拟机里跑。

## sandbox 里 `shell_run` 超时不会杀掉命令

**含义：** 在宿主机上，`shell_run` 的超时会真的杀掉进程。容器里没有远程强杀，所以超时由
那一次 HTTP 调用的读超时在客户端执行：模型会被告知命令超时，而命令**仍在容器里继续跑**，
直到容器自身的租约把它回收。它的副作用可能在"已报告超时"之后才落地。

**何时撞上：** 超过超时时间的构建或测试。

**变通：** 把超时的 sandbox `shell_run` 当作"可能还在跑"，先观察再重试；确实很长的命令
显式给更大的 timeout。同样的原因，容器下拒绝后台 shell 命令。

## 删除空闲容器不可逆

**含义：** 空闲回收有两级。`docker stop`（`SANDBOX_IDLE_STOP_HOURS`）归还内存与 CPU，
容器本体、写入层和端口映射都保留，恢复时数秒 attach。`docker rm`
（`SANDBOX_IDLE_REMOVE_HOURS`）回收磁盘 —— 而被删掉的容器**无法重建**，因为它的规格
只存在于 `docker run` 那一刻。

**何时撞上：** 回到一个容器已被删除的会话。项目目录毫发无损，只存在于容器里的东西没了。

**变通：** 让 remove TTL 显著大于 stop TTL（默认就是 1 小时 vs 24 小时），并把成果留在
项目目录里 —— 那是 bind mount，什么都扛得住。

## 容器属于项目，不属于会话

**含义：** 一个容器服务该项目的所有会话。因此回收判据是「该项目没有任何会话 running 或
waiting」—— 一个忙碌会话会替所有会话把容器保活 —— 而删除一个会话从不释放它。

**何时撞上：** 以为每个会话有自己的容器，或以为删会话能释放资源。

**变通：** 删项目才会释放它的容器。

## 预览面板靠 token，不是鉴权

**含义：** 容器的浏览器与终端被重新发布在**另一个 origin** 上，用一个不可猜的 token
（`secrets.token_urlsafe(16)`）保护。容器凭证只走 gateway→容器这一段、从不到达浏览器；
但浏览器→gateway 这一段除了 token 之外没有鉴权。那个 origin 只提供
`/sandbox-preview/<token>/*` —— 没有 API、没有 SPA、没有我们的 cookie —— 这也正是这些
iframe 可以带 `allow-same-origin` 的原因。

**何时撞上：** 通过只转发主端口的隧道访问，或者期待网络级访问控制。

**变通：** 固定 `SANDBOX_PREVIEW_PORT` 并一并转发；整体保持在 localhost。

## 表格是只读的

**含义：** 二进制工作簿完全不解析。表格类 artifact 会走下载而不是编辑器。

**为什么这样：** 显而易见的那个模型（一张字符串网格、只取第一个 sheet）在保存时会毁掉
其它所有 sheet、全部公式和全部格式。少一个功能，好过丢数据。见
[artifact-trust-model](../../adr/artifact-trust-model.md)（英文）。

## artifact 核实有上限

**含义：** 每轮最多核实 80 个候选。很长的对话可能推导出更多，多出来的保持未核实状态，
因而也不可收集。

**变通：** 实际上不需要 —— 面板会降级成"前 N 个已核实"，而不是报错。

## 没有带外通知

**含义：** agent 提问时任务会持久地等下去 —— 但没有任何东西来通知你。没有 webhook、
没有邮件、没有系统通知。应用内的通知中心只能触达一个开着的浏览器标签页。

**变通：** 让标签页开着；侧边栏会标出正在等待的会话，以及你不在时跑完的会话。

## mock 模式的保真度

**含义：** 离线 mock 只演一条固定链路。在一个已经有 `report.md` 的项目里重跑，会产生一次
**失败**的写入（agent 的先读后写规则），而固定台词照样宣称成功。

**何时撞上：** 往同一个目录演示第二次。

**变通：** 换一个新的项目目录，或者接上真实网关。
